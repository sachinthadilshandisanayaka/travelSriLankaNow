Theme System — How It Works

Zero-flash theme switching via Docker environment variable. No code changes required between deployments.

Full Flow
1
Server
Set THEME_PRESET in .env
The only file you touch. One line determines the entire visual theme of the deployment.
.env
THEME_PRESET=warm
2
Docker
docker-compose passes it into the container
Docker Compose reads the .env file automatically and injects the value as an environment variable inside the running container.
docker-compose.yml
frontend:
  environment:
    THEME_PRESET: ${THEME_PRESET:-navy}   # navy if not set
3
Container startup
generate-theme.sh runs before nginx
This script is the container's startup command. It reads THEME_PRESET, writes the correct CSS colour variables to assets/theme.css, then starts nginx. Everything happens before any request is served.
generate-theme.sh (Docker CMD)
THEME="${THEME_PRESET:-navy}"

case "$THEME" in
  warm) cat > /usr/share/nginx/html/assets/theme.css << 'EOF'
    :root { --primary-navy: #FF8F00; --primary-navy-dark: #C62828; ... }
  EOF ;;
  *)    cat > /usr/share/nginx/html/assets/theme.css << 'EOF'
    :root { --primary-navy: #1C4D8D; --primary-navy-dark: #0F2854; ... }
  EOF ;;
esac

exec nginx -g "daemon off;"
4
Browser
theme.css loads before Angular
index.html links the theme stylesheet first, before the Angular bundle. The browser applies the CSS variables to :root before any component renders — no colour flash.
index.html (load order)
<link rel="stylesheet" href="assets/theme.css">  ← loads first
<script src="main.js"></script>               ← Angular starts after
5
CSS
Every component reads CSS variables at render time
All SCSS files were compiled with var(--primary-navy) references — not hardcoded hex values. The browser resolves the correct colour from whatever theme was written in step 3.
compiled styles.css (baked at Angular build time)
.navbar  { background: var(--primary-navy); }
.btn     { background: var(--gradient-primary); }
.section { background: var(--navy-bg-lightest); }
Available Themes
Navy default
THEME_PRESET=navy
Warm red · gold
THEME_PRESET=warm
Switching Themes
StepAction
1Edit .env on the server — set THEME_PRESET to the desired theme name
2Rebuild and restart the frontend container
3Site is immediately themed — no Angular rebuild required
docker compose up -d --build frontend
The Angular bundle never changes between themes. Only theme.css is rewritten at container startup. The JavaScript build is cached; only the nginx image layer is recreated.
Scope
Changes with themeDoes NOT change
Navbar, footer, buttonsAdmin panel (has its own colour system)
Page headers, section backgroundsSocial media button colours (platform brand colours)
Floating action buttonError / success / warning semantic colours
Cards, filters, paginationWhite, black, neutral greys
Gradient overlays on imagesTypography (same font stack across themes)
Adding a New Theme

Open travelSrilankaNow/generate-theme.sh and add a new case block.

generate-theme.sh
case "$THEME" in
  warm) ... ;;
  navy) ... ;;

  forest)   # ← new theme
    cat > "$THEME_FILE" << 'EOF'
    :root {
      --primary-navy-dark: #1B4332;
      --primary-navy:      #2D6A4F;
      --primary-blue:      #52B788;
      --primary-sky:       #D8F3DC;
      /* also add --primary-navy-a40, --primary-navy-a50, etc. */
    }
EOF
    ;;
esac
Also add the pre-computed rgba() alpha variants for the new colours (e.g. --primary-navy-a40), matching the pattern already in the file for navy and warm.
